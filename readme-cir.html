Chriz Item Randomiser

Author: Christopher Hermann (GitHub).
Built on: Item Randomiser by Fredrik Lindgren, also known as Wisp.
Version: 1.0.3 (releases).
Languages: English; Polish game texts where Item Randomiser has them. The extended pools' reward texts and the texts of the options “Include Kangaxx items” and “Cursed disguise item” also in German. In other game languages these options show their English texts, and the quests that show reward texts stay out of the extended pools (translations welcome).

Overview

Chriz Item Randomiser (CIR) shuffles where items are found in Baldur's Gate, anew for each adventure you start. It works while you play, through EEex: each new adventure gets its own randomisation when its first character is accepted, and saves keep the randomisation they started with. You choose what is randomised in the configurator; changing those settings for the next adventure needs no reinstallation.

CIR is a new mod built on Wisp's Item Randomiser. It reuses that mod's item and location lists, item files and texts, and it cannot be combined with Item Randomiser's own randomisation (Mode 1 or Mode 2) or its “More Spell Shield scrolls” component; the configurator offers that option for each adventure instead. If one of them is installed after CIR, the configurator does not apply settings, and with Mode 1 or Mode 2 new adventures start only without randomisation.

Requirements

  • Baldur's Gate: Enhanced Edition, Baldur's Gate II: Enhanced Edition or the Enhanced Edition Trilogy (EET). If your store installed Siege of Dragonspear as a DLC archive (sod-dlc.zip), merge it into the game first, for example with DLC Merger; the installer stops and says so otherwise.
  • EEex with its LuaJIT component. Start the game with InfinityLoader.exe.

The optional components below need neither: they also install on Baldur's Gate II: Enhanced Edition, and the scroll component on Baldur's Gate: Enhanced Edition as well.

Installation

Extract the archive into the game folder so the cir folder is beside chitin.key, then run setup-cir. The Windows package (the archive whose name ends in -windows.zip) contains setup-cir.exe, a copy of WeiDU, and the configurator; with the mod archive alone, supply a current WeiDU executable as setup-cir. Install CIR after every mod that changes the user interface or the new-game template (UI.MENU, BALDUR.GAM).

The quest and conversation changes CIR relies on are made when it is installed and removed when it is uninstalled. They only take effect in adventures whose settings use them. If another mod changed one of those files so that the change cannot be made safely, the installer says so, leaves the file as it is, and the configurator does not offer what depends on it.

Optional components

These come from Item Randomiser 8.1.1 and keep its component numbers. Each can be installed on its own; do not install one together with Item Randomiser's own version of it (the installer refuses Cespenar's and the Duergar merchant's).

  • Cespenar can forge SoA items (9000): in Throne of Bhaal, Cespenar can also forge the nine items Cromwell forges in Shadows of Amn: Ankheg Plate Mail, Red Dragon Scale, Shadow Dragon Scale, Crom Faeyr, the Equalizer, the Short Bow of Gesen, Wave, the Silver Sword and the Mace of Disruption +2. He offers them first when he looks through your belongings; declining one leads to the next, then to his own recipes. Where he already has a recipe for a dragon scale (the Shadow Dragon's in the Enhanced Editions), only his own is offered for it.
  • Remove Protection from Undead scrolls from stores: from all stores (10100), or from nine stores in ten (10200). Which stores keep them is chosen at random when the component is installed and only changes when it is reinstalled. The installer says how many stores it changed.
  • Duergar merchants (10210): one of the Duergar merchants in the Underdark has regular wares and special wares. Normally, once you can buy his special wares you can no longer buy his regular ones; with this component you can buy both.
  • Prevent Watcher's Keep statues from disappearing (10300): on the first level of Watcher's Keep, the game removes some statues, and moves the level's spawns, for a small or weak party. This component keeps the level as it is for any other party, so the statues and their items stay. Only that adjustment is changed; other scripts of the level, including other mods' blocks, stay as they are. If another mod (such as SCS) has already made this change, or the level has no such adjustment, the installer says so and changes nothing.

Configuration

Installing CIR changes nothing in play until a configuration is applied. After the whole mod stack is installed, close the game and double-click cir-configurator.exe in the cir folder. It scans the game it is in and opens the configurator in your web browser, where you choose the settings and apply them; keep its window open until you are done. It needs no Python or other runtime and runs on Windows 10 and later. It is not signed, so Windows may ask before its first start. It comes with the Windows package; the mod archive alone does not contain it.

A configuration can start from a preset: Item Randomiser's original lists (the default), or Boss Loot, aShuN's lists for Baldur's Gate 1, which put powerful items at difficult boss fights, the ability tomes on the main path and wizard items at mage enemies. In EET, Boss Loot changes the Baldur's Gate 1 part; Baldur's Gate II keeps the original lists. Siege of Dragonspear has no lists of its own yet, so its items stay where the game puts them. The configurator offers the presets your game has: those for Baldur's Gate 1 in BG:EE, those for Baldur's Gate II in BG2:EE, all of them in EET. Each chosen item and recipient shows its part of the game (BG1, SoD, BG2, Watcher's Keep, ToB) and, from a preset, its tier; you can find them by name, resource ID, item type, part or tier. Item Randomiser's special places, such as a reward someone hands over or one that waits at a corpse, carry a mark and a short description, and any configuration can choose them. Places on creatures that can leave alive, turn into another creature or never appear are left out, so that their rewards cannot be lost; the preset dialog says how many.

Applied settings cover every campaign you can start: Baldur's Gate and Siege of Dragonspear in BG:EE, Shadows of Amn and Throne of Bhaal in BG2:EE, all four in EET. An adventure that starts later in the saga, such as a Throne of Bhaal start, randomises only the rewards and places it can reach; the others stay where the game puts them, so no item ends up where you cannot go. After applying, the configurator says which starts are randomised.

When a new adventure cannot be randomised (for example the Black Pits, a start the settings have nothing for, or a game started without EEex), the game says why and lets you start it without the randomiser or cancel.

Uninstallation

Uninstalling CIR with WeiDU removes its runtime and its quest and conversation changes; each optional component is uninstalled on its own. Settings applied with the configurator are not recorded by WeiDU and stay in randomiser-campaigns. Adventures that were randomised may miss items after CIR is uninstalled.

Version history

  • 1.0.3 (2026-10-29): more of Item Randomiser's places and rewards can be used, and a reward whose recipient is gone is no longer lost. Install CIR again and apply your settings again to use them in new adventures; adventures started with an earlier version keep their randomisation.
    • New places and rewards of the extended pools, which were left out in every game as quests CIR could not change yet: in the Sahuagin city, King Ixilthetocal's place, his bracer and his treasury, and Prince Villynaty's two places (whichever of the two you help hands over his rewards, the treasury's comes with the king's payment, and the other's lie at his corpse); Tolgerias's payment for Valygar, which otherwise lies at his corpse in the planar sphere; Jermien's reward for the mimic's blood; the troll in Spellhold and TorGal in the de'Arnise keep (with flail heads); the four places of the guild war in chapter 3, carried by one of Bodhi's vampires or lying at the corpse of one of Aran's shadow thieves or of Aran himself, depending on the side you fight; the two scrolls of the book in Spellhold (with spell scrolls); and in Baldur's Gate, Varci's shield, Aldeth's sword and Nemphre's scroll (with spell scrolls), also with Boss Loot.
    • Adalon now hands over her place's reward when you return her eggs. Before, the reward left with her, unless you killed her.
    • The reward for returning Adalon's eggs now goes to the party member who talks to her. Before, it never arrived. In adventures started with 1.0.2, it arrives too: if you returned the eggs there already, your main character gets it after about a minute of play.
    • When a reward moves, the second copy of it that Item Randomiser's lists name in a shop, creature or container is removed, as Item Randomiser's installer does; CIR did this for four creatures only. The Sahuagin king no longer gives out a second rod when the treasury's rod moves.
    • Rewards that a mod changed can be used: the rewards that Talon Yarryl, Khan Zahraa, Captain Dennis, the priest of Waukeen in Amkethran and Lasaonar carry, where a mod changed these creatures, and items that a mod marked as stolen or gave other flags, such as Baeloth's in Boss Loot. They keep those flags.
    • A reward whose recipient died before it arrived now lies on the ground at the corpse; before, it was never placed. A reward whose recipient vanished without a body, such as a vampire turning into mist, is dropped at a party member's feet, and a message says so.
    • CIR no longer stops working when a reward's recipient is hit, killed, or gets or loses other items just as its reward arrives, as can happen in a fight or a scene. A reward whose recipient dies right then ends up with the recipient's other items: at the corpse, or with a party member. If the recipient leaves no body, the reward is dropped at a party member's feet, and a message says so.
    • CIR no longer stops working when a creature or container gets a reward with the name of the item CIR took from it, such as its own item back (as with the kuo-toa prince's bracers in the Underdark). This also applies to adventures started with an earlier version; where CIR stopped this way, load a save from before it.
    • CIR no longer stops working when the party leaves an area within seconds of first entering it and returns after visiting other areas, or when a creature that CIR took its item from leaves its area within those seconds. This also applies to adventures started with an earlier version; where CIR stopped this way, load a save from before it.
    • CIR no longer stops working when the party leaves an area just as a reward is handed over there, or when a save made at that moment is loaded. On the party's next visit, CIR checks whether the reward arrived, and hands it over otherwise; the other rewards go on meanwhile. This also applies to adventures started with an earlier version; where CIR stopped this way, or an earlier version made the save at that moment, load a save from before it.
    • CIR no longer stops working when the party enters an area where a randomised item lies in a pile on the ground rather than in a container, such as the Ulcaster dungeon in Baldur's Gate and two areas of Watcher's Keep: the game moves such a pile slightly when it loads the area, and CIR did not recognise it there. This also applies to adventures started with an earlier version; where CIR stopped this way, load a save from before it.
    • A quest reward meant for a party member who is not in the party when it is handed over now goes to your main character instead of waiting for them, and CIR no longer stops working when that party member leaves just as the reward is handed over. Where the game lost track of who should get a quest reward, your main character gets it after about a minute of play.
    • Places on creatures that can leave alive, turn into another creature or never appear are left out, so that their rewards cannot be lost; of a group of possible carriers, only such members are left out. So are places on creatures that CIR cannot tell apart from another creature in their area. The preset dialog says how many places are left out and why.
    • A conversation in which someone hands over a reward they carry no longer holds them for good once CIR has stopped working in the adventure, so the quest can go on; the reward stays with them. The message that CIR stopped also opens a popup now, since it was easy to miss in the message log.
    • Configurator: the editor marks Item Randomiser's special places with a short description, and any configuration can choose them. Presets offer only the options the game can apply (BG:EE was offered Kangaxx's items and more Spell Shield copies, which Apply then refused). “Include Kangaxx items” and “Cursed disguise item” work in every game language: German games show German texts with the German game's own item names, Polish games Item Randomiser's Polish texts, all others the English texts; before, Apply refused them in games that were not English. “More Spell Shield copies” no longer makes a preset fail where the scroll's shop row cannot be randomised. The preset dialog tells the rows that wait for a quest CIR cannot change yet apart from those the game cannot use. After an Apply that wrote quest files, the configurator's next start no longer sets the applied settings aside (“cannot be reopened”). Apply no longer refuses with “Close this game and its installer” because of another game's installer that had just ended.
  • 1.0.2 (2026-10-24): the game no longer slows down while CIR has items left to place. CIR checked its whole state on every game tick, which in large configurations, such as the extended pools, made the game run at a fraction of its speed from the start of a new game; it now does a small share of these checks on each tick. This also applies to adventures started with an earlier version. The game also starts quickly again after many Applies: CIR prepared its checks for every setting applied so far while the game started (about half a minute and much memory with seven of them); it now prepares only those of the game you start or load, when you start or load it (about a second in our tests). CIR no longer stops when it gives a creature or a container a scroll, potion, ammunition or other stackable item. The game creates such an item with a count of 1 where the item lists say 0 (the default), and CIR took that for an error: it showed "Chriz Item Randomiser stopped working in this adventure" and placed no further items, so creatures such as mages lacked their randomised items (with randomised scrolls this happened early). In a game where that message appeared, load a save from before it or start a new game. Items that CIR puts into shops are now identified, like the shop's own goods; most of them were unidentified before. Items already in a shop in a game started with an earlier version stay unidentified; they can be identified after buying them, as usual. The configurator's options “More Spell Shield copies” and “Cursed disguise item” now work: a preset with either of them was refused with “These selections belong to a different scan or an unsupported draft”, because the configurator's check did not know the settings these options add. A new adventure with a large configuration, such as Item Randomiser's original lists with the extended pools in EET, no longer fails with “could not randomise this adventure” (“main function has more than 65536 constants” in last-error.txt): the configurator now writes such settings in parts that the game's Lua can load. Apply your settings again to replace the files of an earlier version. Cancel in that message, and in the other messages that New Game and Import can show, now returns to the start screen; before, it left the screen black (BG:EE, EET) or without buttons (BG2:EE). The configurator builds presets two to four times as fast and checks them about twice as fast, shows how long each longer action has been running and how long it took, and reports the result of Apply once instead of twice. It shows each chosen item's and recipient's part of the game (BG1, SoD, BG2, Watcher's Keep, ToB) and tier, and the type of each item, and finds them by name, resource ID, item type, part or tier.
  • 1.0.1 (2026-10-20): installs with SCS, IWDification and other mods that route character creation through their own Lua files: the installer now redirects New Game, character import and character acceptance in every menu and Lua file of the user interface, and names the file and line of anything it cannot redirect. The configurator leaves out a creature, area or store file it cannot read, with a note, instead of refusing the game; checks that the game is closed without WMI, which other software can keep too busy to answer; keeps the settings older saves use when it applies from a new data folder (for example after reinstalling Windows); and no longer speaks of a test game.
  • 1.0.0 (2026-10-19): first version.
